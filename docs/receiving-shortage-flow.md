# 부족 검수와 추가 입고 구현 명세

관련 문서 [OpenAPI](openapi.yaml) · [정상 입고](receiving-normal-flow.md) · [보충 이행 상태](fulfillment-state-design.md)

## 업무와 화면

최초 검수는 박스당 한 건이다. 각 출고 항목의 정상 확인 수량을 0부터 박스 출고 수량까지 입력한다. 부족분은 박스 항목별 조사 건으로 생성한다. 해당 수량은 운송 중 미해결에 남으며 매장 정상 재고에는 실물 확인 수량만 반영한다. 검수 상태는 CONFIRMED가 되고 요청은 FULFILLING에 머문다.

도착 매장 직원은 박스 조회에서 부족 건 ID와 잔량을 확인하고 실제로 추가 도착한 수량을 등록한다. 등록할 수량은 1 이상이며 현재 부족 잔량 이하여야 한다. 일부만 도착하면 OPEN을 유지하고, 잔량이 0이면 RESOLVED로 종결한다. 모든 박스의 최초 검수와 부족 건이 종결되고 열린 잔량·예약·운송 중 수량이 0이면 요청은 COMPLETED가 된다. 분실 처리와 파손은 후속 범위다.

## API와 재전송

- 기존 최초 검수 경로와 정상 입고 응답 형식을 유지한다. 최초 검수 요청의 수량은 0도 허용하며, 누락·중복 항목과 출고량 초과는 400이다. 응답의 박스 상세에 부족 건 정보가 포함된다.
- 추가 입고 경로는 박스의 부족 건 ID를 사용한다. 도착 매장 직원만 실행하며 요청·출고·박스·부족 건의 소속을 모두 검증한다. 범위 내에서 존재하지 않는 부족 건은 404다.
- 두 명령 모두 인증·접근 검증 후 요청 행을 잠그고 기존 성공 기록을 확인한다. 최초 검수는 기존 RECEIPT 키 범위와 해시를 유지한다. 추가 입고는 ADDITIONAL_RECEIPT를 쓰고 부족 건 ID·기대 버전·수량을 해시에 포함한다. 같은 키와 같은 입력은 당시 201을 반환하고 다른 입력은 IDEMPOTENCY_CONFLICT다.
- 새 추가 입고 명령은 기대 버전 검증 후 부족 건 상태·잔량을 확인한다. 오래된 버전은 VERSION_CONFLICT, 현재 잔량보다 큰 수량이나 이미 종결된 건은 RECEIPT_SHORTAGE_CONFLICT다. 실패한 명령은 키를 소비하지 않는다.

## Flyway V4와 원장

| 대상 | 변경 |
|---|---|
| receiving_inspection_item | 최초 검수의 received_qty CHECK를 0 이상으로 변경 |
| receiving_shortage | 최초 검수 상세 FK UNIQUE, 최초 부족 수량 양수, 미해결 잔량이 0 이상이고 최초 부족량 이하. 상태는 잔량에서 계산 |
| additional_receipt | 부족 건 FK, 추가 입고 수량 양수, 처리자 FK, 확정 시각. 최초 검수와 별도 추가 전용 기록 |
| additional_receipt_stock_movement | 추가 입고 ID를 PK/FK로 사용하고 매장 잔액 FK, 양수 normal_delta, 기록 시각 저장 |

최초 확인량이 0이면 검수 상세와 부족 건을 보존하고 해당 항목의 재고 갱신 및 원장 생성은 생략한다. 확정된 최초 수량과 추가 입고 이력은 수정하지 않는다. 박스 항목의 총 입고는 최초 수량과 추가 입고의 합이고, 운송 중 미해결은 출고량에서 그 합을 뺀 값이다. 출고 상세의 운송 중 수량도 같은 기준으로 계산한다.

## 트랜잭션

요청 → 박스 → 부족 건 → 매장·SKU 재고 키 순으로 잠근다. 최초 검수는 기존 박스당 UNIQUE를 유지하며, 확인 수량과 부족 건을 같은 트랜잭션에 저장한다. 추가 입고는 부족 건의 현재 잔량을 확인하고 그 수량을 차감한 뒤 추가 입고와 매장 재고·원장을 반영한다. 두 명령 모두 요청 버전을 한 번 증가시키고 요청 상태·이력과 성공 응답을 같은 트랜잭션에 저장한다. 재고 또는 원장 저장 실패 시 검수·부족량·요청 버전·명령 기록도 롤백한다.

## 인수 기준

| 시나리오 | 기대 결과 |
|---|---|
| 6장 출고 후 5장 최초 검수 | 박스 CONFIRMED, 매장 정상 +5, 부족 1 OPEN, 운송 중 1, 요청 FULFILLING |
| 추가 1장 | 원본 검수 5 유지, 추가 입고 원장 +1, 부족 RESOLVED, 운송 중 0, 요청 COMPLETED |
| 같은 추가 입고 재전송 | 기존 201과 추가 입고 ID 반환, 매장 정상 합계 6 유지 |
| 두 명이 부족 1장을 동시에 등록 | 한 건만 성공. 나머지는 VERSION_CONFLICT 또는 최신 버전으로 시도 시 RECEIPT_SHORTAGE_CONFLICT |
| 부족 1장에 추가 2장, 타 매장에서 등록 | 각각 409, 403. 수량과 원장 변경 없음 |
| 추가 입고 원장 실패 | 부족 1, 운송 중 1, 매장 정상 5와 이전 요청 버전 유지 |

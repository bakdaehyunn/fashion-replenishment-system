# 피킹 부족과 부분 출고 구현 명세

관련 문서 [OpenAPI](openapi.yaml) · [정상 출고](outbound-normal-flow.md) · [보충 이행 상태](fulfillment-state-design.md) · [WMS 시뮬레이터](wms-simulator-spec.md)

## 첫 시나리오

업무 장부의 창고 정상 재고는 7장이고, 시뮬레이터 실물은 5장이다. 매장이 7장을 신청하고 담당자가 전량을 예약한다. WMS는 다른 위치까지 확인한 뒤 확보 5장·부족 2장을 확정해 통지한다. 시뮬레이터에서 확보 수량은 해당 지시가 점유하며 출고 또는 취소 전에는 다른 작업이 사용할 수 없다.

| 단계 | 창고 정상 | 창고 예약 | 조사 보류 | 열린 잔량 | 출고 누계 | 운송 중 |
|---|---:|---:|---:|---:|---:|---:|
| 승인 후 | 7 | 7 | 0 | 0 | 0 | 0 |
| 최종 피킹 결과 반영 후 | 5 | 5 | 2 | 2 | 0 | 0 |
| 5장 출고 후 | 0 | 0 | 2 | 2 | 5 | 5 |
| 5장 정상 입고 후 | 0 | 0 | 2 | 2 | 5 | 0 |

조사 보류 2장은 장부상 수량이다. 실사로 발견하면 정상 재고로 돌리고, 손실을 확정하면 보류 장부에서 차감한다. 두 경우 모두 승인된 조정 이력을 남긴다. 예약을 풀어 가용 재고에 즉시 반환하는 경로는 허용하지 않는다. 창고 정상 재고와 유효 예약은 같은 수량만큼 줄어 가용 재고가 늘지 않는다.

## 상태 및 명령

| 현재 | 입력과 조건 | 다음 상태와 효과 |
|---|---|---|
| WORKING | 최종 피킹 이벤트에서 부족량 양수 | PICKING_EXCEPTION. 부족량만큼 배정·예약 해제, 정상에서 조사 보류로 이동, 열린 잔량 복원 |
| PICKING_EXCEPTION | 물류 담당자가 부분 이행 허용 건의 확보 수량을 확정. 확보량 합계 양수 | 출고 지시 상태 유지, 승인된 수량과 release Outbox 저장 |
| PICKING_EXCEPTION | 승인된 확보분 포장 이벤트 | READY_TO_SHIP |
| READY_TO_SHIP | 승인 수량과 일치하는 최종 출고 이벤트 | SHIPPED. 실제 출고량만 정상·예약에서 차감하고 박스 항목으로 운송 중 수량 생성 |
| PICKING_EXCEPTION | 부분 이행 불허 또는 확보량 0 | 출고 승인 거절. 취소 확인 후 남은 예약을 처리하고 전체 재확보 여부를 결정 |

출고 결정은 담당자가 확인한 피킹 리비전에 고정한다. 이 단계에서는 확보 수량을 그대로 승인하며 임의 추가 감량은 다루지 않는다. 출고 승인 요청의 중복은 기존 명령 멱등성 구조로 관리한다. 취소 확인 중인 지시에는 새 출고 승인을 허용하지 않는다. 이미 전송된 출고 승인과 취소가 경합하면 WMS 지시 행 잠금으로 최종 결과를 결정한다.

5장이 입고되어도 미배정 2장이 남아 있으므로 요청은 FULFILLING이다. 재고 조사 건도 독립적으로 완료를 차단한다. 열린 잔량은 추가 승인·새 출고로 이행하거나, 담당자가 수량과 사유를 기록해 미충족 종결한다. 창고 조사 종결과 요청 잔량 종결은 별도 업무다.

## WMS 메시지와 수량 의미

- `PICKING_FINALIZED`는 모든 지시 항목의 `lineId`, `skuCode`, `pickedQty`, `shortageQty`와 `workId`, `revision`을 포함한다. 모든 항목에서 확보량과 부족량의 합은 지시량이어야 한다. 이벤트 ID와 지시별 순번으로 중복을 막는다.
- `POST /wms/v1/runs/{runId}/orders/{externalOrderId}/release`는 `commandId`, `revision`, 승인한 `lines[{lineId,quantity}]`를 받는다. 양수 확보 항목만 포함한다. WMS는 같은 commandId와 본문에 저장한 응답을 반환한다. 같은 ID의 다른 본문은 409다. 취소·출고로 이미 종결됐거나 리비전과 확보량이 불일치해도 409로 처리한다.
- 부분 출고의 `PACKING_COMPLETED`는 승인된 양수 항목만 박스에 넣는다. `SHIPMENT_CONFIRMED`의 박스 합계는 승인량과 일치하고, `unshippedLines[{lineId,quantity}]`에는 지시량과 실제 출고량의 차이만 기록한다. 이미 피킹 단계에서 해제한 부족량을 확정 이벤트에서 다시 해제하지 않는다.
- 전량 확보 지시는 기존 자동 출고 계약을 유지한다. 시뮬레이터의 실물 재고와 피킹 점유량은 별도로 관리하고, 부분 출고 결정 대기 동안 실물 재고를 차감하지 않는다.

## DB 및 잠금

| 대상 | 변경 |
|---|---|
| 출고 지시·항목 | 항목별 확보량·부족량, 피킹 리비전, 승인 식별 및 확정 수량을 저장 |
| 예약 배정 | `지시 배정량 = 미처리 + 소비 + 해제`를 유지. 여러 예약을 사용하는 항목은 예약 ID 순으로 부족 해제·출고 소비를 나눈다 |
| 창고 피킹 차이 | 출고 상세·피킹 근거와 연결. 조사 보류량, 사유, 발생·조정 이력을 저장 |
| release Outbox | 명령 ID 유니크. 승인 변경과 함께 커밋 후 외부 호출 |
| 재고 원장 | 부족 보류 전환을 정상 −2·보류 +2·예약 −2로 기록. 출고 증감과 구분 |
| 복수 출고 | 현재 출고의 요청 FK UNIQUE를 제거하고 활성 지시 한 건으로 제한한다. 기존 지시 조회는 요청 ID와 지시 ID를 함께 검증한다 |

잠금 순서는 요청 → 출고 지시 → 거점·SKU 재고 → 예약 배정이다. 이벤트 반영과 상태·원장·Inbox 커서는 하나의 트랜잭션에 둔다. 부족 이벤트에서 참조된 예약이 충분하지 않거나 다른 요청의 예약을 침범하면 전부 롤백하고 조사 대상으로 표시한다.

복수 출고를 연결할 때는 현재 단일 `outboundOrderId` 응답에 출고 목록을 추가하고, 완료 판정이 요청의 모든 출고·박스·차이 건을 포함하게 바꾼다. 전량 허용이 필요한 건은 신규 지시 전에 기존 부족 지시의 취소를 확정하고 전량 확보를 요구한다.

## 검증 기준

- 7장 예약 → 5장 확보·2장 부족. 조사 보류를 만들고 다른 요청에 2장을 예약할 수 없어야 한다.
- 부분 이행 허용 건에서 담당자 승인 전에는 출고 이벤트가 생성되지 않는다. 승인 후 5장만 출고하고, 같은 승인이나 출고 이벤트 재전송은 재고를 다시 변경하지 않는다.
- 부분 이행 불허 또는 전량 부족 건은 강제로 출고할 수 없다.
- 5장 입고 후에는 운송 중 0, 열린 잔량 2로 이행 중 상태가 유지된다.
- 추가 출고로 2장을 이행하거나 사유를 기록해 종결하고 창고 조사도 처리하면 완료된다.
- 부족 적용 중 원장이 실패하면 예약 상세, 정상·보류·예약 잔액, 출고 상태와 Inbox 커서를 모두 롤백한다.

## 미충족 종결 구현

물류 운영 담당자가 항목의 열린 잔량 전체를 종결한다. 별도 API에서 창고 조사 전체를 실물 발견 또는 손실로 종결한다. 조사 조정은 창고 업무 장부를 변경하며, 실물 확인은 외부 WMS에서 완료됐다고 가정한다. 한쪽의 종결이 다른 쪽의 증감이나 이력을 대신하지 않는다.

두 명령은 동일 요청 행 잠금 아래 버전·멱등성·권한을 검사하고, 중앙 완료 판정을 다시 실행한다. 창고 조사 원장은 한 조사당 하나의 조정으로 제한하며 재고 증감과 함께 커밋된다. 5장 정상 입고와 미충족 2장 종결, 조사 종결이 모두 확인된 결과는 완료 상태와 실제 입고·미충족 수량으로 표시한다.

## 전량 미충족 종결

부분 이행을 허용하지 않은 7장 요청에서 실물 5장만 확보되면 물류 운영 담당자가 출고 지시만 취소할 수 있다. WMS가 취소를 확정할 때 확보분 5장의 예약을 해제한다. 조사 보류 2장은 별도 실사 결과가 확정될 때까지 유지하며, 요청의 열린 잔량은 7장으로 복원된다. 전량을 다시 승인할 수 있고, 재공급할 수 없으면 담당자가 7장을 사유와 함께 미충족 종결한다. 출고 지시와 창고 조사가 종결돼야 요청이 완료되며, 정상 입고 0장과 미충족 7장으로 표시된다. 매장 직원이 요청 전체를 취소하는 흐름은 CANCELLED로 기록한다.

## 같은 요청의 추가 출고

요청은 출고 이력을 여러 건 보유하며 동시에 활성 지시는 한 건이다. V11은 지시를 요청 단위에서 지시 ID 단위로 조회하도록 전환하고, 요청당 활성 지시를 부분 유니크 인덱스로 제한한다. 새 지시는 아직 배정·소비되지 않은 유효 예약만 사용한다. 요청 잠금과 명령 키로 동시 생성 및 재전송을 처리한다. WMS 콜백, 검수, 조사 결과는 각 출고 지시에 귀속된다.

5장 입고 후 발견한 2장은 WMS 실사 결과를 시연용 SQL로 기록하고, 업무 시스템에서 FOUND 조사를 종결해 장부에 복구한다. 같은 요청에 남은 2장을 승인하고 새 외부 지시 ID로 출고한다. 둘째 출고가 취소되면 해당 지시의 예약만 풀어 열린 잔량으로 돌리고 기존 출고·입고를 보존한다.

모든 출고·박스·조사와 열린 수량을 확인해 완료한다. 요청 상세는 모든 출고 지시와 누적 정상 입고량을 반환한다. 5장과 2장의 두 검수 기록을 합산한 정상 입고량은 7장이다.
